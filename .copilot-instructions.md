# GitHub Copilot Instructions for The Lock In Factory

## Project Overview
This is a Flutter-based productivity application called "The Lock In Factory" designed to help users maintain focus and track their productivity sessions. The app uses Firebase for backend services and supports multiple platforms (iOS, Android, macOS, Web).

## Project Structure
```
the_lock_in_factory/
├── lib/
│   ├── main.dart                 # App entry point
│   ├── models/                   # Data models and entities
│   ├── screens/                  # UI screens and pages
│   ├── services/                 # Business logic and API services
│   ├── utils/                    # Utility functions and helpers
│   ├── widgets/                  # Reusable UI components
│   └── wrappers/                 # Service wrappers and abstractions
├── ios/                          # iOS-specific configuration
├── android/                      # Android-specific configuration
├── macos/                        # macOS-specific configuration
├── web/                          # Web-specific configuration
├── assets/                       # Static assets (images, fonts, etc.)
├── test/                         # Unit and widget tests
└── .github/workflows/            # CI/CD pipeline configuration
```

## Development Guidelines

### Code Style
- Follow official Dart style guide
- Use meaningful variable and function names
- Prefer composition over inheritance
- Keep functions small and focused (max 20-30 lines)
- Use proper error handling with try-catch blocks

### Architecture Patterns
- Use repository pattern for data access
- Implement service layer for business logic
- Separate UI logic from business logic
- Use dependency injection for testability

### Flutter Best Practices
- Use `const` constructors where possible
- Implement proper widget lifecycle management
- Use keys for widgets in lists
- Handle async operations properly with FutureBuilder/StreamBuilder
- Implement proper error states and loading indicators

### Firebase Integration
- Initialize Firebase in `main.dart`
- Use Firebase Auth for user management
- Structure Firestore collections logically
- Implement offline support where appropriate
- Handle Firebase exceptions gracefully

### Testing Guidelines
- Write unit tests for all business logic
- Create widget tests for complex UI components
- Mock external dependencies (Firebase, APIs)
- Aim for >80% code coverage
- Use descriptive test names that explain the scenario

### File Organization
- Group related files in appropriate directories
- Use barrel exports (index.dart files) for clean imports
- Keep feature-specific code together
- Separate platform-specific code when necessary

## Common Tasks

### Adding a New Screen
1. Create screen file in `lib/screens/`
2. Add route definition
3. Implement proper navigation
4. Add any required services or models
5. Write corresponding tests

### Adding Firebase Functionality
1. Update Firebase configuration if needed
2. Add new Firestore collections/documents structure

4. Handle authentication requirements

## Troubleshooting Common Issues

### Firebase Setup
- Ensure GoogleService-Info.plist (iOS) and google-services.json (Android) are properly configured
- Check Firebase project settings match app bundle identifiers
- Verify Firebase rules allow proper access

### Build Issues
- Run `flutter clean` and `flutter pub get` to resolve dependency issues
- Update CocoaPods with `pod repo update` for iOS builds
- Check platform-specific configuration files

### Authentication Issues
- Verify OAuth client IDs are correctly configured
- Check Firebase Auth settings
- Ensure proper URL schemes are configured for OAuth flows
